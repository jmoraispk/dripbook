Day 7 · Claude Code: From Basics to Mastery

Hallucination, security, limits and lock-in

Claude Code can hallucinate in multi-step chains. A single step may produce correct output, but errors compound across a chain of ten or twenty steps. A file that was supposed to be read in step three may have been edited by step five and Claude’s understanding of the codebase state becomes stale. This is why verification at each step is essential. Research by Huang et al. (2026) tested seven widely used MCP clients including Claude Code and found that tool-poisoning attacks can inject malicious instructions through data returned from connected external systems [14]. When Claude reads a GitHub README, a database query result, or a Slack message that contains embedded instructions, those instructions become part of its context and can manipulate its behavior.

Claude Code cannot make decisions about business requirements. It can implement what you ask for, but it cannot determine whether a feature should exist, which API design is optimal, or which tradeoffs are acceptable. These are human judgments. The research on 400,000 sessions confirms this: humans make roughly seventy percent of planning decisions while Claude handles about eighty percent of execution decisions [6].

Claude Code introduces real security risks to your development environment. As documented by Check Point Research, CVE-2025-59536 allowed remote code execution through malicious project configuration files before any trust dialog appeared and CVE-2026-21852 enabled API key theft via ANTHROPIC_BASE_URL manipulation [11]. These are documented vulnerabilities that affected real deployments and demonstrated how configuration files, traditionally treated as passive metadata, can become executable attack vectors.

Beyond Claude Code, the broader MCP ecosystem faces systemic security challenges. A vulnerability advisory from Ox Security (April 2026) identified that IDEs and coding assistants including Windsurf, Claude Code, Cursor, Gemini CLI and GitHub Copilot are vulnerable to command injection via their MCP JSON configuration files [17]. The only issued CVE at the time was for Windsurf, but the attack pattern applies across the ecosystem. NIST characterizes prompt injection as “generative AI’s greatest security flaw” and OWASP ranks it as the number one vulnerability in their LLM Applications Top 10 [35].

Claude Code has usage limits and compute constraints. In early 2026, many Pro plan users reported hitting usage limits within ten to fifteen minutes of using Sonnet, with Opus becoming unavailable shortly after starting [27]. Anthropic doubled usage limits in May 2026 in response to compute bottlenecks, but the fundamental constraint remains: Claude Code is a shared resource and heavy usage will eventually hit rate limits [39]. The Pro plan includes $20 per month of agent credits, Max 5x includes $100 and Max 20x includes $200 [2]. For sustained development work, most teams find that upgrading to Max 5x or higher is necessary to avoid interruptions.

Claude Code cannot replace human code review. Every AI-generated change should go through the same review process as developer-written code. Every AI-generated change touching security-critical files should require two reviewers. The agent is a collaborator, not an autonomous shipper [20]. This principle was reinforced by Stripe’s experience: Scott MacVicar, who leads Stripe’s developer infrastructure team, emphasized that treating AI as a replacement rather than a collaborator is the biggest challenge in adoption [8].

Vendor lock-in and ecosystem dependency. Claude Code is designed to work best with Anthropic models and integrates tightly with the Claude platform. While it uses open standards like MCP, migrating away from Claude Code to another agent or back to traditional development carries real costs: learned workflows, CLAUDE.md files, custom skills, hooks and MCP server configurations are all specific to Claude Code. Teams should evaluate whether the productivity gains outweigh the lock-in risk, especially for projects with long lifecycles.

These limitations are not weaknesses of Claude Code per se. They are characteristics of any system that delegates work to an LLM-based agent. Understanding them is the first step toward using Claude Code effectively and safely.
